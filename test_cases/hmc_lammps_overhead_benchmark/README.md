# Hybrid Monte Carlo (HMC) LAMMPS Coupling Overhead and Performance Benchmark

This directory contains the complete benchmarking suite, profiling data, analysis scripts, visualization figures, and publication manuscript for the Hybrid Monte Carlo (HMC) LAMMPS coupling interface in **`MC_Checkerboard`** (prepared for submission to the *Journal of Chemical Theory and Computation*, JCTC).

A symlink to this directory is available at:
```bash
/home/e.lomba/HMC_lammps_jctc_benchmark
```

---

## 1. Scientific Overview & Objectives

In Hybrid Monte Carlo (HMC), canonical Monte Carlo sampling cycles are interleaved with deterministic microcanonical Molecular Dynamics (MD) trajectories generated by an external MD engine (LAMMPS). Coupling a massively parallel GPU-accelerated cellular Monte Carlo code (`MC_Checkerboard`) with LAMMPS introduces several potential performance bottlenecks:

1. **Data Transfer Latencies**: Synchronizing coordinates between GPU checkerboard memory buffers, host memory, and LAMMPS internal data structures (formatted ASCII disk files vs. direct in-memory C/Fortran API pointers).
2. **Task Invocation Paradigms ("Forking")**: The overhead of invoking LAMMPS via OS process forking (`system` / `mpirun lmp`), in-process library re-initialization with environment reset (`clear`), and persistent in-memory library instances.
3. **Potential Representations**: Throughput differences between continuous analytic potential overlays (`hybrid/overlay lj/cut cosine/squared`) and hardware-interpolated tabulated potentials (`pair_style table linear`) with GPU-resident neighbor lists.
4. **Trajectory Crossover Scaling ($N_{\mathrm{md}}^*$)**: Determining the trajectory length where physical MD integration dominates over communication and invocation overhead.

## 2. System and Simulation Specifications

- **Colloidal Model**: Palaia Site--Site Patchy (SSP) colloidal fluid (*ACS Nano* **2022**, 16, 3918).
- **Geometry**: Each colloid consists of 1 central core of diameter $\sigma$ and $n_p = 4$ attractive surface patches arranged in an ideal tetrahedral configuration at radius $r_p = 0.5\sigma$.
- **Colloidal Particle Count**: $N = 7{,}695$ particles.
- **Explicit LAMMPS Interaction Sites**: $N_{\mathrm{sites}} = 5 \times 7{,}695 = 38{,}475$ atoms (1 core + 4 patches per colloid).
- **Composition**: Binary mixture with $N_1 = 1{,}895$ (type 1) and $N_2 = 5{,}800$ (type 2).
- **Thermodynamic State**: Reduced temperature $T^* = 0.15$, number density $\rho = 0.1218$, cubic box length $L = 39.8263\sigma$.
- **HPC Platform**: NVIDIA RTX PRO 4500 GPU (Blackwell architecture, 82 Streaming Multiprocessors, 31.4 GB VRAM) paired with AMD EPYC host processors on the CSIC Ladon supercomputing cluster (`gpu_v4_short` partition).

## 3. Key Findings and Benchmark Results

### A. Data Transfer Breakdown ($38{,}475$ Interaction Sites)
- **Disk-Based ASCII Communication (Baseline)**:
  - Formatted file write to disk (`lammps_hmc.data`): **$47.87$ ms**
  - LAMMPS text token parsing from disk (`read_data`): **$75.01$ ms**
  - **Subtotal Disk Latency**: **$122.88$ ms** ($96.7\%$ of total transfer time).
- **In-Memory API Coordinate Exchange**:
  - Direct coordinate injection (`lammps_scatter_atoms`): **$0.164$ ms**
  - Direct coordinate extraction (`lammps_gather_atoms`): **$0.264$ ms**
  - **Subtotal In-Memory Latency**: **$0.428$ ms**
  - **Speedup**: Direct in-memory pointer transfer is **$287.1\times$ faster** than disk file I/O!
- **Geometric Mappings & GPU Synchronization**:
  - Quaternion $\to 5N$ sites forward mapping: **$0.190$ ms** ($24.7$ ns/colloid)
  - Explicit sites $\to$ rigid-body triad/quaternion inversion: **$0.509$ ms** ($66.1$ ns/colloid)
  - GPU checkerboard $\leftrightarrow$ host cellular synchronization: **$3.52$ ms**
  - **Total roundtrip time drops from $127.10$ ms (disk) to $4.65$ ms (in-memory persistent)**, a **$27.3\times$ overall acceleration**.

### B. Task Invocation & "Forking" Dynamics
- **In-Process Reset Overhead (`clear`)**:
  - `clear` (3.87 ms) + `read_data` (75.01 ms) + script parsing (68.99 ms) + `run 0` GPU neighbor build (203.64 ms) = **$351.51$ ms** fixed penalty per trial.
- **Comparison at $N_{\mathrm{md}} = 50$ steps (Tabulated Potential)**:
  - External OS Process Fork (`mpirun lmp`): **$1.198$ s**
  - In-Process Library with Reset (`clear`): **$1.045$ s**
  - In-Process Persistent Library (`scatter_atoms`): **$0.721$ s** (**$1.66\times$ faster** than process fork).

### C. Tabular vs. Continuous Analytic Potentials on GPU
- **Pure MD Execution Throughput (RTX PRO 4500)**:
  - At $N_{\mathrm{md}} = 50$: Tabulated is $0.716$ s vs. Analytic $4.361$ s (**$6.09\times$ faster**).
  - At $N_{\mathrm{md}} = 100$: Tabulated is $1.355$ s vs. Analytic $8.629$ s (**$6.37\times$ faster**).
  - At $N_{\mathrm{md}} = 500$: Tabulated is $6.452$ s vs. Analytic $42.943$ s (**$6.66\times$ faster**).
- *Mechanism*: Tabulated potentials (`pair_style table linear`) execute with full GPU neighbor lists (`neigh yes`) and hardware-accelerated linear texture interpolation. In contrast, continuous analytic overlays (`hybrid/overlay lj/cut cosine/squared`) fall back to CPU neighbor lists (`neigh no`) with hybrid force additions.

### D. Overhead Fraction & Crossover Trajectory Length ($N_{\mathrm{md}}^*$)
- **Baseline Reset**: Overhead represents $80.5\%$ at $N_{\mathrm{md}} = 0$ and $61.3\%$ at $N_{\mathrm{md}} = 10$. The 50% crossover trajectory length is **$N_{\mathrm{md}}^* \approx 20$ steps**.
- **Persistent In-Memory Execution**: Eliminating environment re-initialization drops the coupling overhead to **$< 1\%$** for all $N_{\mathrm{md}} \ge 25$ steps ($0.64\%$ at $N_{\mathrm{md}} = 50$, $0.07\%$ at $N_{\mathrm{md}} = 500$).

## 5. How to Compile and Reproduce

### Step 1: Environment Setup
Load the required compiler, OpenMPI / HPC-X, and TeX Live modules:
```bash
# Source environment variables for LAMMPS and CUDA
source /home/e.lomba/bin/setup_trj
export OPAL_PREFIX=/yggdrasil/usr_local/modules/x64_v4/software/NVHPC/25.3-CUDA-12.8.0/Linux_x86_64/25.3/comm_libs/12.8/hpcx/hpcx-2.22.1/ompi
export PATH=/usr/bin:$OPAL_PREFIX/bin:/usr/local/modules/x64_v4/software/NVHPC/25.3-CUDA-12.8.0/Linux_x86_64/25.3/compilers/bin:$PATH
export LD_LIBRARY_PATH=$HOME/lammps_latest/build:$OPAL_PREFIX/lib:$LD_LIBRARY_PATH
```

### Step 2: Build the Benchmark Suite
Compile the CUDA Fortran benchmark driver linking against `liblammps.so` and `MCCB-gpu` modules:
```bash
cd /home/e.lomba/MC_Checkerboard/test_cases/hmc_lammps_overhead_benchmark

nvfortran -O3 -cuda -gpu=cc90 -mp -I../../src \
  benchmark_hmc_suite.cuf \
  ../../src/mod_sys.o ../../src/mod_geometry.o ../../src/mod_energy.o \
  ../../src/mod_lammps.o ../../src/mod_cb.o ../../src/mod_quaternion.o \
  ../../src/mod_random.o ../../src/mod_tables.o ../../src/mod_cell.o \
  -L$HOME/lammps_latest/build -llammps \
  -o benchmark_hmc_suite.exe
```

### Step 3: Run the Benchmark Suite on SLURM
Submit the job to the CSIC Ladon GPU queue:
```bash
sbatch run_benchmark.slurm
```
Alternatively, for interactive execution on a GPU node:
```bash
$OPAL_PREFIX/bin/mpirun -np 1 ./benchmark_hmc_suite.exe
```

### Step 4: Regenerate Publication Figure
Run the plotting script with Python:
```bash
python3 plot_hmc_benchmark.py
```

### Step 5: Compile Manuscript PDF
Compile the LaTeX document with `pdflatex`:
```bash
module load texlive/20260310-GCC-13.2.0
pdflatex -interaction=nonstopmode hmc_overhead_benchmark.tex
pdflatex -interaction=nonstopmode hmc_overhead_benchmark.tex
```
